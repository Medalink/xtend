02 Features

Your fork stays yours. Upstream keeps coming.

01

Merges by intent

Every change is a commit that says what you asked for. The agent rebuilds that on upstream's new code.

02

Your check decides

Nothing lands until your tests, and the tests upstream just shipped, pass.

03

All or nothing

Three tries, then it puts everything back and exits non-zero.

04

Remembers resolutions

git rerere replays every conflict it has solved before. The agent only sees new ones.

05

Daily sync, if you want

xtend daily on adds a GitHub Action that syncs every day. A failure emails you.

06

Any agent

Claude Code, Codex, Gemini, Amp, opencode, or your own command.

07

Any language

It runs your project's own check. It never parses code.

08

Owners decide

XTEND.md, GitHub settings and CONTRIBUTING.md say what forks may send.

09

Gives back clean

Ports only the changes you pick onto upstream, one commit each.

10

Safe around agents

Git runs with hooks off. Changed git config or hooks get put back.

11

Asks before it sends

Nothing goes upstream without you picking it, never from CI, one open offer per project.

12

No service

One file, no dependencies. Your GitHub fork holds everything.

# pomo

## What it is
A single-page Pomodoro timer in plain HTML, CSS and browser JavaScript, with no dependencies and no build step.
It has two modes (`focus` 25 min, `break` 5 min), Start/Pause and Reset buttons, and it switches mode automatically when the countdown reaches zero.
Timer logic is pure functions in `timer.js`, tested with Node's built-in `assert`.

## Map
- `index.html`: markup. Loads `timer.js` then `app.js` as classic `<script>` tags (no modules); order matters.
- `timer.js`: pure state logic: `MODES`, `createTimer(mode)`, `tick(t)`, `format(seconds)`. Runs in the browser (globals) and in Node (`module.exports` guard on the last line).
- `app.js`: DOM wiring. Holds `timer` state and the `interval` handle; `render()`, `setMode()`, `toggle()`, `step()`; event listeners at the bottom.
- `style.css`: all styling. Flat selectors, hardcoded hex colors (accent `#d9534f`, text `#3b2f2a`, background `#f6f1eb`).
- `test.js`: Node assertions against `timer.js`; prints `ok` on success.
- `package.json`: `private`, no dependencies, only the `test` script.

## Build, run, test
- Build: none.
- Run: open `index.html` in a browser, or serve the folder, e.g. `npx serve .` or `python -m http.server 8000`, then open `http://localhost:8000`.
- Test: `npm test` (same as `node test.js`). Exit code 0 and `ok` means it passed; a failed `assert` throws and exits non-zero.
- Node 18+ is needed for `node:assert/strict`.

## Extension points
- **New timer mode (e.g. long break):**
  1. Add an entry to `MODES` in `timer.js`: `long: { label: 'Long break', minutes: 15 }`.
  2. Add a tab in `index.html` inside `<nav class="tabs">`: `<button data-mode="long">Long break</button>`. Tabs are wired by the `[data-mode]` selector in `app.js`, so you write no JS for the click.
  3. If it should join the automatic cycle, change the ternary in `step()` in `app.js` (`timer.mode === 'focus' ? 'break' : 'focus'`). That line is the only place that decides which mode comes next.
  Note: `MODES[mode].label` is not read anywhere yet. The tab text is hardcoded in HTML.
- **Change durations:** edit `minutes` in `MODES` (`timer.js`). `test.js` reads `MODES.focus.minutes`, so it keeps passing. The `25:00` placeholder in `index.html` (`#time`) is a literal, but `render()` overwrites it on load.
- **New timer state or behavior (skip, add a minute, counting sessions):** add a pure function to `timer.js` that takes a timer object and returns a new one (copy the `tick` pattern: spread `...t`, never mutate). Add it to the `module.exports` line and assert on it in `test.js`. Then call it from `app.js` as `timer = fn(timer); render()`.
- **New button/control:** add the element with an `id` to `.controls` in `index.html`, then add `$('id').addEventListener('click', ...)` next to the existing listeners at the bottom of `app.js`. Anything visible must be updated inside `render()`.
- **Side effects on completion (sound, notification):** put them in `step()` in `app.js`, in the `if (timer.done)` branch, before `setMode(...)`. `setMode` replaces the timer, so `done` is gone after it.
- **Persistence (localStorage):** save in `render()` or in `toggle`/`setMode`. Restore by replacing the initial `createTimer('focus')` on `app.js` line 1. Keep storage code out of `timer.js` so it stays testable in Node.
- **Styling/theme:** `style.css`. For a theme, pull the repeated hex values into `:root` custom properties rather than adding more literals.
- **New source file:** add a `<script src="...">` to `index.html` in dependency order (before `app.js`). If it holds testable logic, give it the same `if (typeof module !== 'undefined') module.exports = {...}` footer as `timer.js` and `require` it in `test.js`.

## Conventions
- No semicolons, 2-space indent, single quotes, template literals for interpolation.
- Plain function declarations for named logic; arrow functions only for small helpers (`$`) and callbacks.
- Timer state is an immutable plain object `{ mode, remaining, running, done }`. Replace it (`timer = { ...timer, ... }`), never mutate it.
- `remaining` is whole seconds. `format()` turns it into `MM:SS`.
- `timer.js` must stay DOM-free and side-effect-free; it is the only file Node loads.
- No frameworks, bundlers, ES modules or npm dependencies. Shared code moves between files as globals because the scripts are classic `<script>` tags.
- `render()` is the single place that writes to the DOM from state; event handlers update state and then call `render()`.
- Always `clearInterval(interval)` before starting a new interval or swapping the timer (see `setMode`, `toggle`).
- DOM hooks: `id` for single elements (`time`, `start`, `reset`), `data-mode` for mode tabs, the `.active` class for the selected tab.
- Tests: top-level `assert.equal(...)` calls in `test.js` with no test framework, and `console.log('ok')` stays last.

# logsum

## What it is

`logsum` is a small Rust CLI that reads a log file (or stdin) made of lines shaped
`<timestamp> <LEVEL> <message>` and prints how many lines it saw at each level, the ERROR
messages ranked by how often they appear, and how many lines it skipped. It is split into a library
(`logsum` crate: parse, summarize, render) and a thin binary that handles I/O. It has no dependencies
beyond std, uses edition 2021, and is at version 1.0.0.

## Map

- `Cargo.toml`: package manifest (`name = "logsum"`, no `[dependencies]`, no features).
- `Cargo.lock`: lockfile, committed. Regenerate it only by adding dependencies through Cargo.
- `src/lib.rs`: all logic. `Entry`, `Summary`, `parse_line`, `summarize`, `render`.
- `src/main.rs`: binary entry point. Reads `argv[1]` or stdin, calls `logsum::summarize` then `logsum::render`.
- `tests/summary.rs`: integration tests against the public library API, built on a shared `const LOG` fixture.
- `.gitignore`: ignores `target/` only.

## Build, run, test

```sh
cargo build                      # debug build
cargo build --release            # target/release/logsum(.exe)
cargo run -- path/to/app.log     # summarize a file
cat app.log | cargo run          # summarize stdin (PowerShell: Get-Content app.log | cargo run)
cargo test                       # all tests (tests/summary.rs; lib has no unit tests)
cargo test render_               # tests whose names match a filter
cargo fmt --check                # formatting (default rustfmt, no rustfmt.toml)
cargo clippy --all-targets -- -D warnings
```

Exit codes: if the file cannot be read, it prints `logsum: <path>: <err>` to stderr and exits with 1.
A stdin read failure panics (`expect("read stdin")`). Otherwise it exits with 0, even when it skipped lines.

## Extension points

- **New log level** (e.g. `TRACE`, `FATAL`): add it to the allow-list array in `parse_line`
  (`src/lib.rs:22`). Matching is exact and case-sensitive. `counts` is a `BTreeMap`, so output order
  is alphabetical, not by severity. To change that, change `render`, not the map type.
- **Different line format** (other separators, bracketed levels, JSON): change only `parse_line`.
  It must keep returning `Option<Entry>`; `None` means the line counts as `skipped`. Keep
  `summarize` format-agnostic.
- **New statistic** (per-level message counts, first/last timestamp, WARN ranking): add a `pub` field
  to `Summary` (keep `#[derive(Debug, Default)]` working, so the type must implement `Default`), fill it in the
  `Some(e)` arm of `summarize`, and print it in `render`. If you need the timestamp, add a field
  to `Entry` instead of the `_time` discard (`src/lib.rs:19`), and update every `Entry { .. }` literal.
- **New output format** (JSON, CSV, top-N): add a sibling `pub fn render_<fmt>(s: &Summary) -> String`
  in `src/lib.rs` next to `render`. Keep `render` byte-identical, because tests assert exact substrings.
  Choose the format in `main.rs`.
- **CLI flags**: `main.rs` reads positional args by hand with `std::env::args().nth(1)`. For one or two
  flags, keep the hand parsing. Adding `clap` adds a dependency and changes `Cargo.lock`; do it only
  if the flag set grows. Keep I/O and process exit in `main.rs`, and keep `lib.rs` free of I/O.
- **Tests**: add `#[test] fn <behavior_in_snake_case>()` to `tests/summary.rs`. Copy
  `render_lists_common_errors_first` for output checks (assert with `contains`/`ends_with` on exact
  strings, including `\n`) and `counts_levels_and_skips_garbage` for `Summary` fields. Extend `LOG`
  only if every existing assertion still holds. Otherwise add a separate `const`.

## Conventions

- Library functions are free `pub fn`s over `&str` / `&Summary`. No traits, no structs with methods,
  and no `Result` in the library. Parse failure is `Option::None`.
- Use `BTreeMap` for any keyed counts so iteration order is deterministic. Count with
  `*map.entry(k).or_insert(0) += 1`.
- Build output in a `String` with `push_str(&format!(...))` using inline captured args (`{level}`).
  Every output line ends in `\n`. Error lines are indented two spaces: `  {n}x {msg}`.
- Ranking ties sort by count descending, then by key ascending (`b.1.cmp(a.1).then(a.0.cmp(b.0))`).
  Keep that tie-break for new rankings so tests stay deterministic.
- Blank or whitespace-only lines are ignored, not skipped. Lines are `trim()`med before splitting.
  Fields are split on single spaces with `splitn(3, ' ')`, so the message keeps its inner spaces.
- In the binary, prefix error messages with `logsum: `, print them with `eprintln!`, and exit with
  `std::process::exit(1)`.
- Short local names (`s`, `e`, `n`, `out`) are fine. Use doc comments (`///`) only where a format
  needs stating.
- Format with default `rustfmt`. Keep it std-only unless a dependency is clearly worth it.

## Hot zones

The upstream history is a single commit (`logsum 1.0`), which touched every file once. So it shows
no churn yet. Base this list on structure: these are the files that every upstream feature must touch.

- `src/lib.rs`: all logic lives in one 60-line file. Upstream changes to the level list, `Summary`, or

# Tally

## What it is
Tally is a small, dependency-free PHP library and CLI for building a shopping cart
and printing a plain-text invoice with subtotal, 8% tax and total. There is no
Composer, no autoloader and no framework: files are wired together with `require`.

## Map
- `src/Cart.php` — `Tally\Cart` (final): `add()`, `items()`, `subtotal()`, `tax()`, `total()`, `TAX_RATE` constant.
- `src/Invoice.php` — namespaced functions `Tally\formatMoney()` and `Tally\formatInvoice(Cart)`; all output formatting.
- `bin/cart` — CLI entry point; parses `sku=price*qty` args, prints the invoice, exits `2` on a bad arg.
- `tests/run.php` — hand-rolled test runner (`check(name, bool)`), exits `1` on any failure.
- `.gitignore` — ignores `vendor/`, `*.log`, `*.tmp`.

## Build, run, test
Requires PHP 8.0+ (`str_contains`, catch without a variable). No build step, nothing to install.
```sh
php bin/cart pen=1.50*4 book=12*1   # print an invoice; qty defaults to 1 (book=12)
php tests/run.php                   # run all tests; prints ok/FAIL per check, exit 0 = pass
php -l src/Cart.php                 # syntax check a file
```

## Extension points
- **New cart calculation** (discount, shipping, per-item tax): add a public method to
  `src/Cart.php` next to `tax()`; return `float` wrapped in `round(..., 2)`. Make
  `total()` include it if it affects the amount due.
- **Configurable rates**: `TAX_RATE` is a `public const`. To vary it, add a constructor
  parameter defaulting to `self::TAX_RATE` rather than editing the constant in place.
- **New item field** (name, category): extend the array shape in `add()` and update both
  `@var`/`@return` docblocks (`list<array{sku: string, price: float, qty: int}>`).
  Give new parameters defaults so existing `add($sku, $price)` callers keep working.
- **New invoice line or output format**: add a function in `src/Invoice.php` (copy
  `formatInvoice`). Summary rows use `sprintf('%-30s %10s', $label, formatMoney(...))`;
  item rows and the `str_repeat('-', 41)` rule are 41 chars wide — keep widths aligned.
- **Currency formatting**: change only `formatMoney()`; every amount goes through it.
- **New CLI flag or arg syntax**: edit the loop in `bin/cart`. Bad input → `fwrite(STDERR, ...)`
  and `exit(2)`. Update the `// Usage:` comment at the top.
- **New source file**: create `src/<Name>.php` with `namespace Tally;`, then add
  `require __DIR__ . '/../src/<Name>.php';` to both `bin/cart` and `tests/run.php`.
- **New test**: append to `tests/run.php` before the final `exit(...)`:
  `check('short description', <bool expression>);`. Expect exceptions with the
  `$threw = false; try { ... } catch (X) { $threw = true; }` pattern already there.
  CLI tests go through `shell_exec('php ' . escapeshellarg(__DIR__ . '/../bin/cart') . ' ...')`.

## Conventions
- Every PHP file starts with `<?php` then `declare(strict_types=1);`; library code is in `namespace Tally;`.
- Classes are `final`, PascalCase, one per file named after the class. Formatting helpers
  are plain namespaced functions in camelCase (`formatMoney`), not static methods.
- Full scalar type hints and return types on every function; array shapes documented
  with Psalm/PHPStan-style docblocks.
- Money is `float`, rounded to 2 decimals at every public return. Tests compare with `===`
  against exact values (`18.0`, `1.44`), so keep rounding consistent.
- Validate input at the boundary and throw `\InvalidArgumentException` (leading backslash
  inside the namespace) with the offending SKU in the message.
- 4-space indent, opening brace of classes/functions on its own line, PSR-12 style.
- Output strings end with `"\n"`; lines are joined with `implode("\n", $lines)`.
- No third-party dependencies. If you add Composer, `vendor/` is already ignored, but
  then both entry points must switch from `require` to the autoloader.

- `src/Cart.php` — core math. Add new methods instead of rewriting `subtotal()`/`tax()`/`total()`;
  don't change the `add()` signature order or the `items()` array shape.
- `src/Invoice.php` — layout widths and labels. Put custom formats in new functions and leave
  `formatInvoice()` output unchanged, since tests match its text.
- `bin/cart` — keep the arg regex and require list intact; add local behavior in a separate
  block or a new `src/` file it requires.
- `tests/run.php` — append local checks at the end (before `exit`), don't reorder existing ones;
  later checks reuse the same `$cart`.
- `.gitignore` — append local patterns at the bottom.

# streaks

## What it is

A small command-line habit tracker in pure Python, using only the standard library and no dependencies.
Habits and their check-in dates live in a JSON file. `report` prints the current streak of consecutive days for each habit.

## Map

- `tracker.py`: core logic. The store is a plain `dict`: habit name -> sorted list of ISO date strings (`"2026-03-10"`).
  - `load(path)` / `save(path, store)`: the only file I/O. A missing file loads as `{}`. Saves with `indent=2, sort_keys=True`.
  - `add_habit(store, name)`, `check_in(store, name, day)`: mutate the store in place. Raise `ValueError` on a bad name.
  - `streak(store, name, today)`, `report(store, today)`: pure reads that return an `int` / `str`.
- `cli.py`: argument dispatch in `main(argv, path, today, out)`. The module docstring doubles as the usage text.
- `test_tracker.py`: `unittest` suite covering the core functions plus one CLI round trip.
- `.gitignore`: ignores `__pycache__/`, `*.pyc`, `habits.json` (the default data file).

## Build, run, test

There is nothing to build or install. Run from the repo root (imports are flat: `import tracker`).

```sh
python cli.py add run          # create habit "run"
python cli.py done run         # check in today
python cli.py report           # "run: 1 day streak"; also the default with no args
HABITS_FILE=/tmp/h.json python cli.py report   # data file override (default ./habits.json)
```

PowerShell: `$env:HABITS_FILE='C:\tmp\h.json'; python cli.py report`.

Tests:

```sh
python -m unittest -v test_tracker            # all tests
python -m unittest test_tracker.TrackerTests.test_streak   # one test
```

Exit codes from `cli.main`: `0` ok, `1` user error (`ValueError`/`IndexError`), `2` unknown command (prints usage).

## Extension points

- **New CLI subcommand** (e.g. `undo NAME`, `list`): in `cli.py`, add an `elif cmd == "...":` branch inside the `try` in `main`.
  Call a `tracker` function; do not touch the store inline.
  Commands that change the store fall through to `tracker.save(path, store)`. Read-only commands `print(..., file=out)` and `return 0` early, as `report` does.
  Update the usage line in the module docstring at `cli.py:1`.
- **New store operation** (remove habit, un-check a day, rename): add a function to `tracker.py` modeled on `check_in`.
  It takes `(store, name, ...)`, raises `ValueError(f"no such habit: {name}")` for unknown names, and mutates the store in place.
  It returns nothing and does no I/O.
- **New statistic** (longest streak, total check-ins, last N days): add a pure function modeled on `streak(store, name, today)`.
  Always take `today` as a parameter and never call `date.today()` in `tracker.py`.
  If it belongs in the report, extend the f-string in `report`, and update the `test_report` / `test_cli_roundtrip` expectations.
- **Different storage format/location**: keep it inside `load`/`save` so the in-memory dict shape stays the same. `cli.DEFAULT_PATH` reads `HABITS_FILE`.
- **Tests**: add `test_*` methods to `TrackerTests` in `test_tracker.py`.
  Use the fixed dates `D = date(2026, 3, 10)` and `day(n)`, build stores as dict literals, and use `tempfile.TemporaryDirectory()` plus `io.StringIO()` for CLI tests (copy `test_cli_roundtrip`).

## Conventions

- Standard library only. Keep it free of third-party dependencies unless the private copy decides otherwise on purpose.
- Flat modules at the repo root, no package. `snake_case` functions, short one-line module docstrings, almost no comments.
- Store values are ISO date strings, sorted and with no duplicates (`check_in` keeps this invariant). Compare dates via `date.isoformat()`.
- Logic in `tracker.py` is deterministic. "Today", the file path and the output stream are injected (`cli.main(argv, path, today, out)`) so tests never hit the real clock, the cwd or stdout.
- Errors: core functions raise `ValueError` with a lowercase `"<problem>: <name>"` message. Only `cli.main` catches them and turns them into `error: ...` plus exit code `1`.
- Output is plain text, one line per habit, sorted by name.

## Gotchas

- `streak`/`report` index `store[name]` directly. An unknown name raises `KeyError`, which `cli.main` does not catch. Validate first if you expose `streak` per habit.
- `streak` counts from today when today is checked in, otherwise from yesterday. Missing only today does not break a streak (`test_streak`).
- `cli.main` writes the file only after a successful mutating command. A failed command leaves the file untouched.
- The `'missing habit name'` fallback in `cli.main` never fires: an exception object is always truthy, so a missing argument prints `error: list index out of range`. Fix with `str(e) if isinstance(e, ValueError) else 'missing habit name'` if that matters.
- `DEFAULT_PATH` is read once at import time. Set `HABITS_FILE` before importing `cli`, or pass `path=` explicitly.

## Hot zones

The upstream history has one commit ("streaks 1.0") touching every file, so expect any upstream change to land in these:

- `tracker.py`, especially `streak` and `report`: the core. Add new functions next to them rather than rewriting them. If you change report wording, keep it in one f-string.
- `cli.py` `main`: the dispatch chain. Add `elif` branches; do not restructure the `try`/save flow, or merges will conflict.
- `test_tracker.py`: add new test methods (or a new `TestCase` class at the bottom) instead of editing existing assertions.
- `.gitignore`: append local entries at the end.
